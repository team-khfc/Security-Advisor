# 보안길잡이 AI · SecurityAdvisor

공공기관 현업 직원이 사업을 설명하면 AI가 보안 서류 작성을 돕고, ICT인프라·정보보안 담당자가 함께 검토하여 확정하는 서비스입니다. **방화벽 정책 허용 신청서와 정보화사업 보안성검토 신청서**를 지원합니다.

이 저장소 하나에 프론트·백엔드·DB 실행 구성이 들어 있습니다. **심사위원은 Docker만 설치하면 됩니다.** Java, Node.js, PostgreSQL을 직접 설치하거나 다른 저장소를 받을 필요가 없습니다.

> **실제 AI 시연:** `LLM_MODE=live`와 공급자 API 키를 설정합니다. 준비된 로컬 심사용 환경은 기존 연동 도커와 같은 **OpenRouter DeepSeek**에 연결했습니다. 공개 배포용 `.env.example`은 키 없이 설치할 수 있도록 `fake`를 유지하므로, 새로 설치하는 심사위원은 [6절](#6-실제-ai-연결과-검증)을 따라 실제 AI를 연결해야 합니다. API 키는 저장소에 포함하지 않습니다.

## 1. 빠른 설치·실행

준비물: Docker Desktop(Windows/macOS, Linux 컨테이너 모드) 또는 Docker Engine + Compose v2(Linux), 인터넷 연결, 웹 브라우저. 여유 메모리 8GB 이상·디스크 10GB 이상을 권장합니다. 최초 빌드에는 이미지·의존성 다운로드로 수 분 이상 걸릴 수 있습니다.

GitHub에서 **Code → Download ZIP**으로 내려받아 압축을 풀거나 다음 명령을 사용합니다.

```bash
git clone https://github.com/team-khfc/Security-Advisor.git
cd Security-Advisor
```

Windows PowerShell:

```powershell
Copy-Item .env.example .env
docker compose up -d --build
```

macOS / Linux:

```bash
cp .env.example .env
docker compose up -d --build
```

`.env`가 이미 있다면 덮어쓰지 않습니다. 명령은 **이 README와 compose.yaml이 있는 최상위 폴더**에서 실행합니다.

- 접속: **http://localhost:3000/login**
- API 상태: http://localhost:8080/actuator/health (`UP`)
- API 문서: http://localhost:8080/swagger-ui.html
- 3000/8080 포트를 이미 쓰고 있다면 `.env`의 `FRONT_PORT`, `BACK_PORT`를 바꾸고 다시 실행합니다.
- `demo` 컨테이너가 계정과 시연 자료를 만들고 정상 종료한 뒤 화면이 시작됩니다. `demo: Exited (0)`은 정상입니다.

```bash
docker compose ps -a
docker compose logs --tail 30 demo
```

마지막 로그에 `완료: 지정 계정 5개, 사업 14건`이 나오면 준비 완료입니다. DB와 첨부 문서는 전용 Docker 볼륨에 보존됩니다. 재실행은 기존 답변과 시연 진행 상황을 덮어쓰지 않습니다.


검사 항목: 5개 계정 로그인·역할, 단계별 신청 조회, 다른 신청자·미배정 담당자 접근 차단, 협의 기준본·변경 이력, 모의 요약, PDF 파일 서명, 새 신청 생성·조회·파일 첨부·모의 분석·철회. 검사가 끝나면 `[자동 점검]` 철회 신청 1건과 감사 기록이 남습니다. 실제 AI 연결 모드에서는 외부 유료 호출을 자동 검사에서 실행하지 않습니다.

업무를 진행한 뒤에는 최초 시나리오 상태가 달라져 검사가 실패할 수 있습니다. 이 경우 오류 내용을 확인하거나 초기화 후 다시 실행하세요. 자동 검사가 모든 화면·모델의 답변 품질을 보장하는 것은 아닙니다.

원본 저장소의 전체 개발 검사는 프론트 `npm run check`, 백엔드 `./gradlew check`입니다. 이 배포 저장소는 소스 스냅샷과 통합 실행을 검증합니다. 규칙 문서를 루트에 통합했으므로 개발용 전체 검사는 아래 원본 저장소에서 수행하세요.

## 6. 실제 AI 연결과 검증

기존 연동 도커와 맞춘 실제 AI 구성은 다음과 같습니다. 이 값은 2026-11-11 시연 검증 당시 설정이며, 공급자 계정에서 해당 모델 사용 권한이 필요합니다.

| 항목 | 값 |
|---|---|
| 모드 | `LLM_MODE=live` |
| 공급자 | OpenAI 호환 (`OPENAI_COMPATIBLE`) |
| 구성 이름 | `openrouter-deepseek-v4.1-flash-1017` |
| 주소 | `https://openrouter.ai/api/v1` |
| 모델 | `deepseek/deepseek-v4.1-flash-1017` |
| 키 참조 | `OPENROUTER_API_KEY` |
| 용도 | `INTERVIEW`, `SUMMARY`, `DOCUMENT`, `INQUIRY` |
| temperature / 최대 토큰 | `0.2` / `4096` |
| 대기 시간 / 우선순위 | `90`초 / `5` |

협의 결과 요약·최종 초안에 쓰는 `DOCUMENT` 용도는 별도 구성 `openrouter-deepseek-document`가 우선 적용됩니다. 같은 모델·주소·키에 최대 토큰 **8192**, 우선순위 **4**를 사용하며 나머지 값은 위와 같습니다. 새 시연 데이터 생성 시 자동 등록합니다. 이미 초기화한 설치는 관리자 → AI 모델 구성에서 DOCUMENT 전용 구성을 추가하세요. 추론 모델은 생각하는 토큰도 출력 한도에 포함하므로 4096에서는 JSON 본문이 잘릴 수 있습니다. 출력 한도 오류가 표시되면 최대 토큰을 점검하고 다시 요청하세요. 잘린 응답이나 검증되지 않은 근거는 저장하지 않습니다.

현재 PC의 `localhost:3000` 심사용 환경에는 기존 도커의 키를 **Git에서 제외된 로컬 `.env`에만** 연결했습니다. 소스 도커의 계정·DB·문서는 복사하지 않았습니다. 다른 PC에 저장소를 내려받으면 키가 전달되지 않으므로 각 환경에서 설정해야 합니다.

1. `.env`에서 `LLM_MODE=live`로 바꿉니다.
2. 사용할 공급자의 키를 `OPENAI_API_KEY` 또는 `OPENROUTER_API_KEY`에 입력합니다. 키는 Git에 올리지 않습니다.
3. 실행 중인 설치에서는 `docker compose up -d --no-deps --force-recreate app`로 새 환경변수를 반영합니다. 최초 설치는 `docker compose up -d --build`를 사용합니다. 기존 데이터는 유지됩니다.
4. `moon.sw`로 로그인 → **AI 모델 구성**(`/models`)에서 공급자, 주소, 모델명, 키 참조, 용도, 최대 토큰, 대기 시간, 우선순위를 설정하고 연결 시험을 실행합니다. 실제 사용 가능한 모델명은 본인 공급자 계정에서 확인하세요. 기본 예시 모델이 계정에서 지원되지 않을 수 있습니다.
5. 용도는 인터뷰·요약·문서·담당자 질의로 나뉩니다. `apiKeyEnv`에는 키 자체가 아닌 `OPENAI_API_KEY` 같은 이름을 지정합니다. 더 작은 우선순위 값이 먼저 선택됩니다.
6. 키 없는 모의 모드로 만든 과거 요약은 자동으로 실제 AI 요약이 되지 않습니다. 06에서 **AI 협의 결과 다시 요약**을 눌러 새 결과를 만들고, 근거를 확인합니다.

이 구성에서 OpenAI·Ollama 키는 사용하지 않습니다. 쓰지 않는 `OPENAI_API_KEY`, `OLLAMA_API_KEY`는 비워 두거나 해당 구성을 비활성화해, 연결하지 않은 모델 서버를 대체 경로로 시도하지 않도록 합니다. 관리자 화면의 모델별 '키 설정됨'과 실제 응답의 모델 기록을 확인하세요.

### 지정 계정으로 실제 AI 4개 흐름 간단히 검사

시연 01이 미제출 상태이고 시연 06이 최종 검토 상태일 때 다음 명령을 실행합니다. **외부 모델 호출 비용이 발생하며 합성 자료를 해당 모델에 전송합니다.** 일반 smoke나 GitHub CI에서는 이 검사를 자동 실행하지 않습니다.

```bash
docker compose run --rm --no-deps -e DEMO_ORIGIN=http://front:3000 demo node scripts/live-smoke.mjs --confirm-live
```

- **안대웅 `an.dw` / 시연 01:** 합성 기획서 업로드·실제 문서 분석 → 첨부 근거를 사용한 AI 인터뷰
- **박소영 `park.sy` / 시연 06:** 실제 협의 결과 요약 → 근거 키 검증 → AI 최종 보고서 초안 생성
- 각 응답의 모델이 `fake`가 아닌지 검사하고, 최종 초안이 **AI 추론·사람 확인 전**으로 저장되는지 확인합니다.
- 결과는 화면에 남습니다. 시연 01의 파일첨부·대화와 시연 06의 협의 요약·최종 보고서에서 확인하세요. 자동 답변 적용·최종 확인·제출은 하지 않습니다.
- 다시 실행하면 첨부·분석·대화·요약 이력이 추가되고 현재 최종 초안이 갱신됩니다. 수정한 초안을 보존하려면 재실행 전에 별도로 보관하세요.

협의 요약이 '근거가 연결된 요약을 만들지 못했습니다'로 거부되면 잘못된 결과를 저장한 것이 아닙니다. 화면에서 다시 요약하거나 위 명령 끝에 `--step=summary`를 붙여 요약만 재시도할 수 있습니다. 최종 초안만 검사하려면 `--step=final`을 사용합니다. 2026-11-11 실제 검증에서도 첫 요약은 거부되고 한 번의 재시도 후 근거가 유효한 8개 항목이 저장됐습니다.

기존 5개 계정과 기본 시나리오는 유지됩니다. 실제 AI 검증으로 생성한 내용도 시연용 합성 자료에 대한 결과이며 실제 기관의 보안 승인으로 해석하지 않습니다.

OpenAI 호환 모델 서버도 사용할 수 있습니다. 호스트를 `.env`의 `LLM_ALLOWED_HOSTS`에 추가하고 서버를 재생성한 뒤 관리 화면에 `/v1` 엔드포인트를 등록합니다. Docker에서 PC의 모델 서버를 가리킬 때는 보통 `host.docker.internal`을 사용합니다(Linux는 호스트 연결 설정 필요). 별도 모델 서버·가중치는 이 패키지에 포함하지 않습니다. 외부 모델 호출에는 해당 공급자 정책과 비용이 적용됩니다.

**모의 모드의 한계:** AI 인터뷰·문서 요약·최종 초안·담당자 질의는 고정 응답이며, 서버·망 구성 AI 제안은 빈 후보를 반환할 수 있습니다. 실제 모델 성능 시연은 live 설정과 연결 시험 후 수행합니다. 사람이 확인하지 않은 AI 제안은 자동 확정되지 않습니다.

## 7. 중지·재실행·초기화

데이터를 유지하며 중지/재실행:

```bash
docker compose stop
docker compose up -d
```

**이 시연 환경의 DB·첨부 파일·모든 입력을 삭제하고 처음 상태로 재생성**하려는 경우에만:

```bash
docker compose down -v
docker compose up -d --build
```

다른 프로젝트 폴더에서 실행하지 마세요. 이 구성의 프로젝트 이름은 `security-advisor-demo`이고 기존 개발용 Docker 데이터와 분리됩니다. 부분 초기화 실패 시 로그의 원인을 해결한 뒤 위 절차로 다시 만듭니다. 자동 초기화 스크립트는 불완전한 DB에 데이터를 중복 생성하지 않고 중단합니다.

## 8. 문제 해결

| 증상 | 확인할 내용 |
|---|---|
| Docker 연결 오류 | Docker Desktop 실행 여부, Linux 컨테이너 모드 확인 |
| `.env`가 없다는 오류 | 최상위에서 `.env.example`을 `.env`로 복사 |
| port is already allocated | `.env`의 FRONT_PORT/BACK_PORT를 미사용 값으로 변경 |
| 화면이 아직 열리지 않음 | `docker compose logs --tail 50 app demo` 확인. 최초 빌드·DB 준비·데이터 생성 완료까지 대기 |
| demo가 오류로 종료 | 같은 로그에서 API 오류 확인. 중간 실패는 전용 시연 초기화 후 재실행 |
| 로그인 실패 | 위 5개 아이디와 설치 당시 비밀번호 사용. 연속 실패 잠금은 기본 15분 |
| AI 오류/응답 지연 | LLM_MODE·키 참조·허용 호스트·모델명·연결 시험 확인. 직접 입력은 계속 가능 |
| 다른 역할의 메뉴가 보임 | 같은 브라우저 탭끼리 세션 공유. 로그아웃하거나 다른 프로필 사용 |
| 파일 분석 실패 | 먼저 제공된 TXT로 확인. HWP/HWPX 등 형식별 제한은 백엔드 문서 참조 |
