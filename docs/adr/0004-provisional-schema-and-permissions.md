# ADR 0004 · 잠정 필드·권한·검증 범위

- 상태: **개발 시작을 위한 잠정 구현 가정, 기관 업무 승인 전**
- 기록일: 2026-11-06
- 확인 주체: 기획·업무 담당자, 프런트엔드·백엔드 담당자 공동

## 배경

상위 문서는 두 서류·역할 4종·4단계·출처·반환 불변식을 확정합니다. 이 프로토타입은 실행 가능한 API 계약을 위해 아래 최소 필드와 책임을 사용합니다. 아래 표는 기관의 정식 양식·내규를 새로 확정하는 문서가 아닙니다. 명세나 담당자 결정으로 바뀌면 계약·코드·migration·검증을 함께 변경합니다.

## 현재 최소 필드

| key | 한국어 의미 | 담당 | 필수 시점 |
|---|---|---|---|
| `purpose` | 서비스 목적 | APPLICANT | 협의 요청 전 |
| `audience` | 이용 대상 | APPLICANT | 협의 요청 전 |
| `dataTypes` | 처리하는 정보 | APPLICANT | 제출 전 |
| `externalTransfer` | 외부 전송 여부 | APPLICANT | 제출 전, UNKNOWN 미해결 |
| `period` | 운영 기간 | APPLICANT | 제출 전 |
| `dataFlow` | 정보가 이동하는 흐름 | APPLICANT | 제출 전 |
| `operatingEnvironment` | 운영 환경 | INFRA | 제출 전·할당 판단 |
| `accessControl` | 접근 통제 방안 | SECURITY | 제출 전 |
| `retention` | 보관·파기 방안 | SECURITY | 보안성검토 제출 전, 방화벽 선택 |
| `logging` | 접속 기록 관리 | SECURITY | 보안성검토 제출 전, 방화벽 선택 |

게시된 추가 질문은 `key`, `label`, `reason`, 담당 역할, 필수 여부를 갖습니다. 관리자 자신을 질문 담당으로 지정하지 않습니다. 질문 목록은 신청 생성 시점 정책에 고정합니다. 텍스트형 추가 질문의 범위이며 복합 조건·파일형 질문은 구현하지 않았습니다.

방화벽의 통신 규칙은 출발지·목적지 이름/IP, 프로토콜·포트·방향, 시작/종료일·목적·출처·확인 정보입니다. INFRA만 이를 입력·확인합니다. 초기 검증 한계는 IPv4, CIDR /24~ /32, 포트 1~65535의 최대 1024개 범위, 적용 날짜 차이 366일입니다. 이 숫자는 시연 입력 제한이며 기관의 허용 정책으로 간주하지 않습니다.

## 현재 권한 가정

| 업무 | 현재 구현 | 확인할 후속 사항 |
|---|---|---|
| 신청 조회 | 작성자는 본인; 전문 담당자는 같은 기관의 협의 공개 이후 신청 | 실제 담당자 개인 배정·대리 업무 범위 |
| 기관 관리자 | 정책·컨텍스트·모델 설정, 신청 목록은 403 | 운영 관리자와 업무 열람 권한의 조직 승인 |
| SECURITY 시작 | INFRA 할당 뒤 | 예외 업무·긴급 절차는 1차에서 추가하지 않음 |
| 최종 확정 | 두 분야 최종 검토가 끝나면 INFRA 또는 SECURITY | 기관의 최종 결재 책임·추가 결재선 |
| 반환 | 2/4단계 전문 담당자, 3단계 작성자 | 반환 항목 의존성과 책임의 업무 검토 |
| 종결·철회 | 전문 담당자 종결, 작성자 철회 | 확정 후 철회·재개·재신청에 대한 운영 정책 |
| 비공개 컨텍스트 | ADMIN의 등록·메타데이터 조회, 별도 암호화 | 열람·삭제·보존 기간과 키 순환 운영 |

## 출처 이름과 보존

현재 API는 `USER_ANSWER`, `AI_INFERRED`, `STAFF_INPUT`, `STAFF_CONFIRMED`를 canonical 출처 이름으로 사용합니다. 상위 문서의 네 의미를 유지하며 이전 식별자 별칭은 파서에서 호환합니다. `confirmation`은 별도 정보이므로 사람이 확인한 AI 값도 AI 원출처가 사라지지 않습니다.

반환은 `returnItems`에 사유·필드·단계·직접/영향 지정·시각·반환 당시 `previousValue`를 기록합니다. 현재 필드 값과 비교하되 이전 값과 이전 제출본을 삭제하지 않습니다.

## 확정 절차

팀이 필드·책임·종결 조건을 검토하여 PROJECT_CONTEXT의 결정 또는 후속 ADR로 승인한 뒤 상태를 변경합니다. 사용자 지침의 확정 불변식은 이 잠정 가정으로 약화하거나 우회하지 않습니다.
