## 문서 개요

보안길잡이 모의데이터는 여섯 묶음이며, 첨부용 문서 3종을 뺀 나머지는 통합 배포본을 Docker로 실행하면 자동으로 준비됩니다. 이 문서는 참가 안내서의 제출물 "모의데이터(선택)"에 맞춰 묶음별 파일명, 용도, 투입 방법을 정리한 것입니다.

| 항목 | 내용 |
| --- | --- |
| 대회 요건 | 개인정보 등 민감자료를 제외한 모의데이터 (참가 안내서 4. 제출물 안내, 세션 1·2) |
| 구동안내서 연계 | 양식 2-1의 "모의데이터 안내" 칸에 파일명·용도·투입 방법을 적습니다. 아래 "구성 한눈에 보기" 표를 그대로 옮길 수 있습니다. |
| 기준 배포본 | Security-Advisor 통합 배포본, 태그 v1.0.2-demo.20261111 |
| 생성 결과 검증 기록 | 배포본의 docs/JUDGE_VALIDATION.md (2026-11-11, 계정 5개·사업 14건·신청 15건·제출본 및 PDF 5건) |

## 작성 원칙

사업·기획서·서버·망 구성·검토 의견·처리 이력은 모두 가상으로 구성했고, 고객 정보·실제 장비 주소·비공개 규정·API 키는 들어 있지 않습니다.

| 구분 | 적용한 기준 |
| --- | --- |
| 표식 | 모의 사업명은 [시연 01]~[시연 14]로 시작하고, 첨부 문서 첫 줄은 [시연용 합성 …]입니다. 방화벽 적용 기록에는 "실제 장비 변경 없음" 문구가 들어갑니다. |
| 개인정보 | 고객 이름·연락처·주민등록번호가 없습니다. 답변이 들어간 모의 신청 10건의 "개인정보 처리 여부" 답변은 모두 "아니요"입니다. |
| IP 주소 | 모의 신청과 첨부 문서의 주소는 문서 예제용 대역(192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24)만 씁니다. 기관 정보 예시 레코드 3건은 사설 대역 10.0.0.0/16의 합성 값입니다. |
| 날짜 | 설치일 기준으로 만듭니다. 사업 기간과 허용 기간은 설치일부터 1년 뒤까지입니다. |
| 비밀값 | API 키는 포함하지 않습니다. .env.example에는 공개된 로컬 시연용 기본값만 있습니다. |
| 실제 장비 | 방화벽 적용·적용 불가·회수는 기록만 남기며 장비를 바꾸지 않습니다. |
| 기관·계정 표시값 | 운영 기관명은 .env의 INSTITUTION_NAME 값이며 배포본 기본값은 참가 기관명입니다. 첨부용 기획서 2종에도 같은 기관명과 부서 표시값이 적혀 있습니다. 시연용 계정의 표시 이름은 참가 팀원 이름이고, 사내 인증과 연결되지 않습니다. |

## 시연용 계정과 운영 기관

시연용 계정은 역할 4종에 맞춘 5개이며, 모두 같은 시연 비밀번호를 씁니다.

| 아이디 | 역할 | 부서 표시값 | 모의 사업에서 맡는 일 |
| --- | --- | --- | --- |
| an.dw | 신청자 | 유동화자산처 | 홀수 번호 시연 사업(01, 03, …, 13)의 신청자 |
| park.sy | 신청자 | 주택연금처 | 짝수 번호 시연 사업(02, 04, …, 14)의 신청자 |
| kim.dh | ICT인프라 담당자 | ICT인프라실 | ICT인프라 분야 기본 담당자 |
| jung.ys | 정보보안 담당자 | 정보보호처 | 정보보안 분야 기본 담당자 |
| moon.sw | 기관관리자 | ICT운영실 | 업무 지표, 설정·지식 관리, AI 모델 구성 |

비밀번호: .env의 DEMO_ACCOUNT_PASSWORD 값입니다. 기본값은 .env.example과 README에 공개된 로컬 시연 전용 값이며, 서버에는 해시로 저장됩니다. 최초 실행 뒤에 이 값만 바꿔도 이미 만든 계정의 비밀번호는 바뀌지 않습니다.

운영 기관: .env의 INSTITUTION_NAME·INSTITUTION_CODE로 정합니다. 배포본 .env.example의 값은 한국주택금융공사 · HF-DEMO이고, 이 두 항목을 두지 않으면 서버 기본값 "합성 시연 기관" · DEMO가 쓰입니다.

서버 내장 계정: applicant, applicant2, security, infra, admin(표시 이름은 김신청·박신청·이보안·박인프라·최관리, 합성)은 서버가 처음 켜질 때 만들어지고, 시연 초기화가 끝나면 비활성화됩니다.

동시 촬영: 같은 브라우저 프로필의 탭은 로그인 세션을 공유하므로, 역할을 함께 띄울 때는 프로필을 나눕니다.

## 투입과 초기화 방법

모의데이터는 따로 넣는 절차 없이 설치 명령 두 줄로 들어갑니다. Docker만 있으면 되고 Java·Node.js·PostgreSQL을 따로 설치하지 않습니다.

배포본 루트에서 .env.example을 .env로 복사합니다. Windows PowerShell은 Copy-Item .env.example .env, macOS·Linux는 cp .env.example .env입니다.

docker compose up -d --build를 실행합니다. 서버가 처음 켜질 때 DB에 설정 게시본·합성 지식 6건·기관 정보 레코드 4건이 들어가고, 이어서 demo 서비스가 계정 5개와 모의 사업 14건을 만듭니다.

docker compose logs --tail 30 demo에 "완료: 지정 계정 5개, 사업 14건"이 보이면 준비가 끝난 것입니다. demo의 Exited (0)은 정상입니다.

localhost:3000/login에서 시연용 계정으로 로그인하고, 목록에서 [시연 01]처럼 검색합니다.

첨부용 문서는 신청 화면에서 samples/의 파일을 골라 첨부한 뒤 분석을 요청합니다.

| 상황 | 명령 | 모의데이터에 생기는 일 |
| --- | --- | --- |
| 중지 후 재실행 | docker compose stop → docker compose up -d | 그대로 보존. 초기화 스크립트는 완료 표시를 보고 건너뜀 |
| 처음 상태로 되돌리기 | docker compose down -v → docker compose up -d --build | DB·첨부 문서·모든 입력을 지우고 다시 생성 |
| 생성된 번호 확인 | docker compose run --rm --no-deps demo cat /state/scenarios.json | 변경 없음. 시연 번호별 사업·신청 번호를 보여 줌 |
| 자동 점검 | docker compose --profile test run --rm smoke | 철회된 자동 점검 신청 1건이 추가됨. 시연 01~14의 상태는 바꾸지 않음 |
| 실제 AI 연동 점검 | README의 scripts/live-smoke.mjs --confirm-live | 모의데이터를 외부 모델로 보내고, 결과를 시연 01·06에 저장함 |

초기화가 중간에 실패한 볼륨에서는 스크립트가 중복 생성을 막기 위해 멈추므로, "처음 상태로 되돌리기"를 실행합니다.

## 모의 AI 응답과 유의 사항

기본 설정(LLM_MODE=fake)에서는 외부 모델을 호출하지 않고 아래 고정 문구를 돌려줍니다. 실제 모델의 분석 결과가 아니며, 응답에 기록되는 모델 이름은 fake/offline 또는 fake/consultation입니다.

| 기능 | 모의 응답 |
| --- | --- |
| 문서 분석 요약 | "합성 요약: 입력 문서의 핵심을 요약한 것으로 가정한 고정 응답입니다." |
| AI 인터뷰 | "합성 AI 설명입니다. 사업에서 알고 있는 사실을 확인해 입력해 주세요." 추천 답변은 "합성 사업 개요 추천답변입니다." |
| 항목별 제안 | "합성 제안(항목 키)". 근거로 첫 번째 지식 조각을 붙이고, 지식이 없으면 제안하지 않음 |
| 필요한 서류 제안 | "합성 근거: 개요에 외부 연동·신규 서비스가 언급됨" |
| 협의 결과 요약 | "모의 요약입니다. 실제 AI 분석을 수행하지 않았습니다. 사업정보와 협의 비교 항목을 직접 확인해 주세요." |
| 최종 초안 | "합성 초안: 확정된 값으로 채운 서류 초안으로 가정한 고정 응답입니다." |
| 담당자 AI 질의 | "합성 답변입니다." 뒤에 참고한 기관 사실과 근거의 첫 줄을 붙임 |
| 서버 구성 AI 제안 | 빈 제안(서버·통신 구간 없음) |

실제 AI 시연: .env에서 LLM_MODE=live로 바꾸고 키를 넣어야 모의데이터를 실제 모델이 분석합니다. 이때 모의데이터가 외부 모델 공급자에게 전송됩니다.

업무 지표: 관리자 지표 화면의 수치는 모의 신청에서 계산한 값이며 실제 업무 효과를 뜻하지 않습니다.

날짜: 기간과 기한이 설치일 기준이라, 설치한 날에 따라 화면의 날짜가 달라집니다.

자동 점검: 자동 점검은 초기 상태의 모의데이터를 전제로 합니다. 시연 사업의 상태를 바꾼 뒤에는 실패할 수 있습니다.

개발용 모의 API: front/mocks/는 화면만 따로 개발할 때 쓰는 별도 합성 데이터입니다. 통합 배포본은 실제 서버에 연결해 실행하므로 이 데이터를 쓰지 않습니다.
