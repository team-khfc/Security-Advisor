# ADR 0003 · 4단계 업무와 원본 디자인 적용

- 상태: 확정 업무 규칙 반영
- 기록일: 2026-11-06
- 근거: FUNCTIONAL_SPEC v1.2, design v3.1, prototype 지정 커밋

## 업무 결정

신청 애그리거트가 4단계, 기관·작성자·담당 분야 권한, 출처·사람 확인, 수정 revision, 반환과 종료 규칙을 강제합니다. 역할과 기관을 클라이언트 입력으로 정하지 않습니다.

2단계는 INFRA 자원 할당이 선행하며 할당 완료와 INFRA 협의 완료를 분리합니다. 두 분야의 현재 자료 검토가 끝나야 3단계로 갑니다. 최종 AI 초안의 보완분도 미확정이며 사용자가 확인한 뒤 제출합니다. 4단계에서 두 담당 분야의 제출본 최종 검토 후 서류를 확정합니다. 실제 장비 적용은 별도입니다.

반환은 2→1, 3→2, 3→1, 4→3만 지원하고 사유·항목이 필수입니다. 기존 값과 이력을 유지하며 선택·영향 항목의 확인과 검토를 무효화합니다. 종결·철회도 사유와 이력을 남깁니다. 제출 시 정책·값·문서를 해당 차수에 보존하고 재제출은 새 차수입니다. 제출·게시의 멱등 키는 중복 생성과 결과 혼동을 방지합니다.

## 디자인 적용

원본은 `team-khfc/prototype` 커밋 `3900181bc85440780b199266a75f1b789f76f2d0`의 디자인 패키지이고 화면 규칙은 루트 `design.md` v3.1입니다. 원본 HTML의 업무 구조·공급 토큰·라이선스를 기준으로 Next.js 화면을 연결합니다. 실제 상태 변경은 서버 API가 판단합니다.

원본 정적 패키지 전체는 이 실행 저장소에 복제하지 않습니다. 원본의 브라우저 저장 기반 가짜 상태·역할 선택·파일 형식 예시가 실제 구현 지원 범위와 혼동되지 않도록 원본 링크와 매핑을 제공합니다. 폰트·CSS 등 사용한 자산과 라이선스는 THIRD_PARTY_NOTICES에 표시합니다.

`/design-preview/*`는 로그인 없이 보는 합성 읽기 전용 화면입니다. 업무 API 저장·제출의 검증 증거로 사용하지 않습니다. KRDS 기반 구현과 KRDS 전체 준수·접근성 인증을 구분합니다.

## 후속

필드·권한 가정은 ADR 0004에서 별도로 확정해야 합니다. 공휴일 제외 업무일 기한, 모든 보조공학 환경과 확대 검수는 구현·검증 근거가 생기기 전 완료로 표시하지 않습니다.
